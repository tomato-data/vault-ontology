## 1 · 갈림길 규칙을 지금 정할 것인가 ⭐

### 무엇이 문제인가

판정 결과 역량 질문 30개 중 18개가 「그 사실이 vault에 적혀 있지 않다」였다.
그런데 **적기만 하면 기존 SQLite가 답하는 것이 그중 12개**다. 실증했다.

```python
# vault/graph.py:83 — 엣지의 kind 는 frontmatter 필드 이름에서 그대로 온다
for kind in ("builds_on", "supersedes"):
```

여기에 `"evidence", "contradicts"` 두 개를 더하고 문서에 그 필드를 적자,
C04·C05·C06이 **RDF도 온톨로지도 없이** 답해졌다.

문서보다 작은 단위가 필요한 질문만 3부를 정당화한다. 그런데 그게 필요한지는
**Phase 10.5 파일럿이 재기 전까지 모른다.**

### 선택지

| | |
|---|---|
| **A. 갈림길 규칙을 미리 적는다** (권장) | 「파일럿에서 문서 단위로 충분하다고 나오면, frontmatter 필드를 늘리고 3부를 닫는다」를 지금 문서에 적는다 |
| B. 파일럿 결과를 보고 그때 정한다 | 유연하지만, 결과를 보고 나면 이미 들인 시간이 판단에 섞인다 |
| C. 결과와 무관하게 온톨로지까지 간다 | 목적이 학습이라면 정당하다. 다만 그렇다고 명시해야 한다 |

### 권장 — A

2부가 정확히 여기서 넘어졌다. 다 만든 뒤에 「SQLite로 이미 된다」가 나왔다.
이번에는 **만들기 전에** 갈림길을 안다. 미리 적어두면 나중에 기준을 유리하게
옮기지 못한다. 이 프로젝트가 파일럿 중단 기준을 미리 적은 것과 같은 이유다.

C를 고르셔도 됩니다. 단 그때는 **「3부의 목적은 vault 강화가 아니라 온톨로지
학습이다」**라고 `part3-boundary.md`의 목표를 고쳐 적어야 합니다. 두 목적은
성공 기준이 다릅니다.

## 2 · Phase 순서를 다시 배치할 것인가

### 무엇이 문제인가

현재 순서는 이렇다.

```
10.5 파일럿  →  11 정체성(ID)  →  12 어휘  →  13 작성 계약
```

판정은 **작성 계약이 18/30으로 압도적**이라고 말한다. 그리고 Phase 11은 마이그
레이션할 데이터가 0개인 상태에서 ID를 정하고, Phase 12는 인스턴스가 0개인 상태
에서 어휘를 정한다.

즉 **무엇을 적을지 모르는 채로 어떻게 식별할지를 먼저 정하는 순서**다.

### 선택지

| | |
|---|---|
| **A. 13을 11·12 앞으로 당긴다** (권장) | `10.5 → 13 → 11 → 12`. 파일럿의 임시 표기를 정식 작성 계약으로 굳히고, 그 계약이 요구하는 것에 맞춰 ID와 어휘를 정한다 |
| B. 문서 순서대로 간다 | phase13이 「artifact와 knowledge entity의 ID」를 전제하므로 11이 먼저라는 논리는 성립한다 |

### 권장 — A

B의 논리는 파일럿이 이미 무력화한다. 파일럿은 **임시 표기로** 라벨링하기로 되어
있고, 그 임시 ID로 Phase 13까지 갈 수 있다. 정식 ID는 무엇을 식별해야 하는지가
정해진 뒤에 정하는 것이 싸다.

A를 고르면 [`NEXT.md`](NEXT.md)와 [`README.md`](README.md)의 순서표를 고칩니다.

## 7 · 발견된 결함 세 가지 — 지금 고칠 것인가

전부 3부와 별개입니다. 고칠지 여부만 정해주시면 됩니다.

### 7a · `000 Index/Templates/` 9개의 `type` 오분류

템플릿이 자기가 만들 문서의 type을 달고 있습니다. `Decision Node Template.md`가
`type: decision`, `Daily Template.md`가 `type: log`입니다.

통계 영향은 작습니다 (decision 45 중 1, source-note 1,256 중 7). 다만 Phase 8의
역할 계층에서 `v:Structural`이어야 할 것이 `v:Content`로 들어가 있습니다.

→ **권장: 고친다.** 9개 파일의 `type`을 `template`으로. 10분이면 됩니다.

### 7b · `vault lint` 368 vs 그래프 1,191

같은 「미해결 링크」를 두 도구가 3배 넘게 다르게 셉니다. 첨부 처리 규칙 때문인지
lint 제외 설정 때문인지 **확인하지 않았습니다.**

→ **권장: 조사한다.** 두 도구가 같은 것을 다르게 세는 것은 그 자체로 신뢰 문제
입니다. 다만 3부 진행을 막지는 않으니 별건으로.

### 7c · `supersedes` 5건이 전부 미해결

「대체됨」 관계가 vault에서 사실상 작동하지 않습니다. 5건 모두 대상 문서가
없습니다. C12가 기각된 이유이기도 합니다.

| | |
|---|---|
| A. 관계를 살린다 | 작성 계약에 「폐기」 상태를 넣고 실제로 쓰기 시작한다 |
| B. 버린다 | 안 쓰는 관계임을 인정하고 어휘에서 뺀다 |
| **C. 파일럿에서 판단한다** (권장) | 8~10개 라벨링에서 `supersedes`가 필요해지는지 본다 |
