# 로드맵 — vault-cli 재구현과 온톨로지 학습

> **현재 위치와 다음 작업은 [`NEXT.md`](NEXT.md)에 있다.** 재개할 때 그 파일부터 읽는다.

## 이 프로젝트가 답하려는 질문

Obsidian vault의 문서 6,452개는 위키링크 24,969개로 이미 연결돼 있다. 사람 눈에는 그래프인데 기계가 읽을 수 있는 구조가 없다. `vault-cli`가 그걸 SQLite로 뽑아냈다 — **동작한다. 하지만 내가 짜지 않았다.**

그래서 두 가지를 동시에 한다.

1. **손으로 다시 짠다** — 파서·검증·그래프 빌더를 백지에서 구현한다. 기존 `vault.py`는 회귀 대조본이다
2. **온톨로지를 제대로 배운다** — 같은 vault를 RDF로 다시 모델링하고, SPARQL로 질의하고, 추론기를 돌린다

두 번째가 이 저장소의 존재 이유다. 스키마 설계 문서에 이미 적어둔 문장 때문이다.

> **속성 그래프(Neo4j) ≠ 온톨로지.** 형식 의미론도 추론기도 없다. 온톨로지를 배우려면 RDF 계열이 맞다.

즉 지금 `vault.py`의 `build`/`q`는 **지식 그래프이지 온톨로지가 아니다.** Phase 1~5로 그걸 재현하고, Phase 6~9에서 진짜 온톨로지로 넘어간다. 같은 데이터로 두 번 모델링해봐야 그 차이가 말이 아니라 경험으로 남는다.

## 큰 그림

```
                  ┌──────────── 마크다운 6,452개 (원본) ────────────┐
                  │                                                │
   Phase 1~3      │  파싱                                          │
   ─────────      │    frontmatter · 위키링크 · 파일 인덱스          │
                  │         ↓                                      │
   Phase 4        │  검증          "만든 것은 반드시 검사를 통과한다"  │
   ─────────      │         ↓                                      │
                  │    ┌────┴─────┐                                │
   Phase 5        │ SQLite 그래프  │  ← 여기까지가 vault.py 재현      │
   ─────────      │ node/edge/tag │     (속성 그래프)                │
                  │               │                                │
   Phase 6~9      │         RDF 트리플  ← 온톨로지 본론              │
   ─────────      │         SPARQL · RDFS/OWL/SKOS · 추론           │
                  └────────────────────────────────────────────────┘
```

**한 단계에 변수 하나씩만 바꾼다.** Phase 5까지의 산출물이 Phase 6~9의 대조본이 된다. 같은 질문("A를 이해하려면 뭘 먼저 읽어야 하나")을 재귀 CTE로 한 번, SPARQL property path로 한 번 푼다. 답은 같아야 하고, 표현력은 달라야 한다.

## 진행 방식

**TDD — RED → GREEN → REFACTOR.** 테스트를 먼저 쓰고, 실패를 보고, 최소로 통과시키고, 정리한다.

파서는 TDD가 특히 잘 맞는다. 함정이 전부 "이 입력에 대해 이 출력"의 형태이기 때문이다. `vault-cli` README의 **"이 자리에서 네 번 잘못 셌다"** 표가 그대로 테스트 케이스 목록이다.

| 함정 | 증상 | Phase |
|---|---|---|
| 표 안의 `\|` | `[[문서\|별칭]]` 타깃 끝에 역슬래시가 남는다 | 2 |
| `splitext` | `No.013 현자의 돌` → `No` + `.013 현자의 돌` | 3 |
| 유니코드 정규화 | macOS는 파일명을 NFD로 저장한다. 본문 링크는 NFC | 3 |
| 대소문자 | macOS는 `python`과 `Python`을 구분하지 않는다 | 3 |
| `\s*(.+)$` | `\s`가 개행을 먹어 빈 `summary:`가 다음 줄을 읽는다 | ✅ 1 |
| `2026-13-99` | 형태는 맞는데 없는 날짜다 | 4 |

각 Phase는 이렇게 돈다.

```
RED       테스트를 쓴다 → 실패 메시지를 함께 읽는다
GREEN     최소 구현 → 통과 → 커밋
REFACTOR  개선점 검토 (없으면 "없다"고 판단하는 것도 결과) → 있으면 별도 커밋
실측       실제 vault에 돌려 답안지 출력과 대조
```

마지막 줄이 중요하다. **단위 테스트가 전부 초록이어도 실제 데이터에서 숫자가 다르면 틀린 것이다.**

## 성공 기준

"코드가 돌아간다"는 성공 기준이 아니다. 도구를 하나 더 만드는 것으로 끝날 위험이 실재하고, 원본 프로젝트 문서도 그 위험을 스스로 적어뒀다 — **지식 정리 자체가 목적이 되어 실제 행동을 미루는 기계가 되는 것**. 그 위험을 알고 시작했다.

- [ ] Phase 5 끝 — 실측값 표를 **손으로 짠 코드로** 재현했는가
- [ ] Phase 8 끝 — vault의 `type` 13값에 **실제로 계층이 있는지** 답을 냈는가 (없다면 없다고 결론내는 것도 답)
- [ ] Phase 9 끝 — 추론이 **SQLite로는 못 얻던 사실을 하나라도** 만들어냈는가
- [ ] 최종 — 미결 판단에 답한다: **"재귀 CTE로 부족한가?"** → v1/v2로 갈지 결정

마지막 항목이 진짜 산출물이다. 원본 설계 문서에는 "2주 써보고 정한다. 지금은 아니다"로 열려 있다.
