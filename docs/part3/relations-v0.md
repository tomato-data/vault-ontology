## 어디서 왔나

역량 질문 30개를 하나씩 판정하며 필요한 관계를 뽑았다. 질문마다 그대로 뽑으면
15개가 나왔고, 합칠 수 있는 것을 합쳐 관계 8개가 됐다가 **2026-08-31에
`violates`를 빼서 7개**가 됐다. 상태·속성은 4개.

phase14의 상한은 관계 10~15개다. **상한이 목표가 아니므로 7개에서 시작한다.**

## 관계 7개

| | 이름 | 나온 질문 | 뜻 |
|---|---|---|---|
| 1 | `derived_from` | C02 C04 C13 C23 C28 | **A는 B에서 나왔다** |
| 2 | `contradicts` | C03 C06 | 양립할 수 없다 |
| 3 | `diverges_from` | C13 | B를 딛되 **바꿨다** |
| 4 | `applies` | C21 C29 | 이 판단이 저 원칙을 적용했다 |
| 6 | `informed_by` | C09 C15 | 영향을 줬다. 근거는 아니지만 흘러들었다 |

### `derived_from` 이 다섯을 흡수한 이유

```
원칙  ← 사건          C04
원칙  ← 저자의 책      C13
원칙  ← 일지 승격      C28
결정  ← 사건          C23
결정  ← 출처 자료      C02
```

전부 **「A는 B에서 나왔다」**다. 출발점의 종류가 다를 뿐이고, 그 종류는 **대상
문서의 `type`이 이미 말한다.** `case`에서 나왔으면 사건이고 `capture`에서
나왔으면 자료다. 관계를 쪼갤 필요가 없다.

### `violates` 를 뺐다 — 2026-08-31

두 표본에서 **0회**였고, 그 뒤에 이유가 나왔다.

```
파일럿 11개 문서    0회
5일 관찰           0회
```

처음에는 「표본이 어긴 기록을 안 담았을 뿐」이라 보고 판정을 미뤘다. 전수로 찾으니
**어긴 기록은 실제로 있었다.**

```
300 Runtime Learnings 8건
   회계 원칙(append-only, 마감 후 불변)을 어겼다
   FSD 레이어 규칙(features → pages 금지) 위반
   아키텍처 규칙 위반 재발 — 수동 5건, 전체 스캔 47건
   규칙 5종 위반 감사표 (건수·심각도·처리 Phase)
```

**그런데 주어가 문서가 아니다.**

```
✗  <Learnings 문서>  violates  <원칙>
✓  <코드·과거의 실행>이 어겼고, <Learnings 문서>는 그것을 기록한 것이다
```

Learnings 문서는 위반이 아니라 **교정**이다. 문서에 `violates`를 달면 주어가 틀린다.
그리고 8건 전부가 **「어겼다 → 고쳤다」로 닫혀 있다.**

#### 왜 0회였는지 — 발견되면 해소된다

토마토의 관찰(2026-08-31, weekly-weave):

> 대답을 하고 문서가 작성되는 시점에서는 그게 문서 단위의 `violates`로 되지 않는
> 경우가 많다. 앞으로 기술적인 것도 `vv`로 관련 사항을 들여다보고, 어긋나면
> **적절히 조화시켜 교정하면서** 작성하게 될 것이다.

실제 사례가 그 주의 weekly-weave 안에 있었다. 「외모는 근본적 불합리」라는 기존
인사이트와 같은 달의 실제 판단이 부딪혔는데, 산출물은 `violates` 엣지가 아니라
**「그 인사이트의 일방향 프레임을 손봐야 한다」**는 개정 제안이었다.

```
violates      쓰는 시점에 발견된다  →  해소된다  →  안 남는다
contradicts   나중에 발견된다      →  아무도 안 고쳤다  →  남는다
```

**두 결정 문서의 팀 규모 임계값(10명 vs 5명)이 아직 그대로인 것**이 `contradicts`가
남는 이유다. 아무도 그것을 조화시키지 않았다.

#### 남는 자리 — 검출이지 사실이 아니다

「어겼다」는 **쓰는 시점의 신호**다. 저장할 사실이 아니라 **그때 띄워야 할 것**이고,
그 자리는 Phase 17(운영 규칙)이다. `vv`가 관련 문서를 띄우고 어긋남이 보이면
사람이 조화시키는 흐름 — weekly-weave가 이미 하고 있는 그것이다.

#### 대가 — C29가 반쪽이 된다

C29(따른 원칙과 어긴 원칙)의 근거는 **「project-doc → principle 110건이 전부
`links_to`이고, 언급·따름·어김이 같은 화살표」**였다.

```
언급했다   →  links_to  (그대로)
따랐다     →  applies   (가른다)
어겼다     →  ✗ 저장하지 않는다. 검출로 옮긴다
```

**「따름 vs 언급」은 갈리고 「따름 vs 어김」은 안 갈린다.** C29를 절반만 답한다.
이 대가를 알고 뺐다.

### `contradicts` 와 `diverges_from` 의 차이

```
contradicts    둘 다 참일 수 없다
diverges_from   저것을 딛고 서되 일부를 바꿨다 — 둘 다 성립할 수 있다
```

C13(원칙이 저자 주장에서 어디를 바꿨는가)이 `diverges_from`이다. 저자를 부정하는
것이 아니라 **겪어보고 고친 것**이므로 충돌이 아니다.

## 상태·속성 4개

관계가 아니라 문서나 사실에 붙는 값이다.

| | 이름 | 나온 질문 | 뜻 |
|---|---|---|---|
| 9 | `status: archived` | C17 | 흥미가 식음. **폐기·오류가 아니다** |
| 10 | `source_unknown` | C02 C13 | **찾아봤고 없었다** |
| 11 | `as_of` | C08 | 이 사실이 언제 유효했나 |
| 12 | `needs_review` | C30 C08 | 재검토 후보. **철회 가능해야 한다** |

### `source_unknown` 이 이 프로젝트다운 항목이다

RDF에서 트리플을 안 쓰면 **「모른다」**다. 이 값을 적으면 **「찾아봤고 없었다」**가
된다. 열린 세계 가정에서 부재를 적극적으로 기록하는 방법이다.

두 번 나온 문제의 해법이다.

```
C02  과거 문서의 출처를 전부 track 하기는 어렵다
C14  필사를 끝내도 참고했다는 사실을 매번 적어야 한다 — 그래서 누락된다
```

**「안 적었다」와 「찾아봤고 없었다」는 다르다.** 앞의 것은 나중에 채울 수 있고
뒤의 것은 더 찾을 필요가 없다.

### `status: archived` 는 폐기가 아니다

이 vault는 PARA를 따른다. 900은 **관심이 옅어진 것**을 옮겨두는 자리이고 복귀가
자유롭다.

```
archived      흥미가 식었다        복귀 가능
deprecated    폐기됐다             대체된 것이 있다
invalid       틀렸다               반증됐다
```

**셋은 다르다.** C12를 기각한 이유가 이것이었다 — vault에 「폐기」가 없는 게 아니라
**다른 것**이 있었다.

## 이름은 영어 문법을 따른다 — 2026-08-31 확정

**한국어 시험 문장과 영어 이름이 어긋나면 영어 문법이 이긴다.** 시험 문장을 비틀지
않고 **이름을 고친다.**

취향의 문제가 아니다.

```
이름이 RDF 술어가 된다
술어는 표준 어휘의 하위 속성으로 매달린다
표준은 영어로 정의돼 있다
   →  이름이 영어로 틀리면 표준과의 연결도 틀린다
```

### 실제로 한 번 틀렸다

`informs` 는 능동태다 — `A informs B` 는 「A가 B에게 알린다」다. 그런데 시험 문장은
**「B가 A에 흘러들었다」**, 즉 반대였다. 그리고 상위 속성으로 매단 것이 이것이다.

```turtle
v:informs rdfs:subPropertyOf prov:wasInfluencedBy .
```

**`prov:wasInfluencedBy` 는 수동태다** — 주어가 영향을 **받는** 쪽이다.
**방향이 반대인 속성을 상위로 매달아놓고 있었다.** 추론기가 승격하면 모든 영향
관계가 뒤집힌다.

**한국어로는 안 보였다.** 시험 문장이 뜻을 맞게 말하고 있어서 이름만 틀린 것을
아무도 못 봤다. `informed_by` 로 고쳤고, 그러자 `answered_by` 와 같은 수동태
계열이 되면서 다른 6개와 방향도 맞았다.

### 그래서 둘의 역할이 다르다

```
한국어 시험 문장    사람이 판정할 때 쓰는 도구
영어 이름          기계가 표준과 잇는 자리
```

**어긋나면 이름이 이긴다.**

## 이름은 영어 `snake_case` 로 쓴다 — 2026-08-26 확정

vault 본문은 한국어지만 frontmatter 키와 관계 이름은 영어다. 기존
`builds_on`·`supersedes`와 같은 자리에 놓이기 때문이다.

**표기는 `snake_case`다.** Phase 14 Step 1이 정했다.

```
frontmatter   derived_from
RDF           v:derived_from      ← 같은 문자열. 변환표가 없다
```

RDF 관례는 `camelCase`지만 `vault-ontology.ttl`이 이미 `v:builds_on`으로 그 관례를
벗어나 있다. 여기서 `camelCase`를 택하면 frontmatter 키와 RDF 이름 사이에 변환표가
생기고, **변환표는 조용히 어긋나는 자리다.**

> 이 문서는 한동안 `camelCase`로, `semantic-authoring.md`와 파일럿은 `snake_case`로
> 적혀 있었다. 어긋난 채로 두 곳이 굴러갔다.
