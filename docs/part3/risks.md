# 3부 위험 장부

> Phase 10 산출물. 2026-08-25.
> 각 위험에 **발생 조건 · 관측 방법 · 완화책 · 중단 조건**을 붙인다.
> 관측 방법이 없는 위험은 위험이 아니라 걱정이다. 그런 항목은 넣지 않는다.

---

## 1군 — 이번 조사에서 실제로 관측된 위험

계획에 없던 항목들이다. **이미 한 번 일어났거나, 일어난 흔적이 남아 있다.**

### R1 · 템플릿이 만든 관계를 사람이 발견한 관계로 오인한다

| | |
|---|---|
| **발생 조건** | 관계 수를 세어 「이 관계는 잘 쓰인다」고 판단할 때 |
| **관측** | `decision ↔ tradeoff` 140건. 판단 타입 4종 중 유일하게 이어진 쌍이다. 그런데 `000 Index/Templates/Decision Node Template.md`와 `Trade-offs Matrix Template.md`가 **짝으로 만들게 강제**한다. 나머지 5쌍 합계는 8건이다 |
| **완화** | 관계를 셀 때 **생성 경로를 함께 본다.** 템플릿·자동화가 만든 것과 사람이 발견한 것을 나눠 센다. Phase 15의 provenance에 「무엇이 이 관계를 만들었나」를 필수 필드로 둔다 |
| **중단** | 3부가 만든 관계의 절반 이상이 자동 생성이면, 그것은 지식이 아니라 스키마다 |

이 위험은 **좋은 숫자일수록 위험하다.** 140은 성공처럼 보인다.

### R2 · 필사를 내 주장으로 다룬다

| | |
|---|---|
| **발생 조건** | `600 Content Observatory`를 대역 단위로 의미 추출에 넣을 때 |
| **관측** | 601 Books 챕터 필사 **914개**. 표본으로 읽은 `A Philosophy of Software Design/Chapter 04`는 저자의 주장만 있고 사용자의 반응이 없었다. `개발 서적 노트 가이드라인`의 개별 노트 규칙은 **「내용 자유 형식」**이라 구분 규칙이 없다 |
| **완화** | 914개를 범위에서 뺀다 ([`part3-boundary.md`](boundary.md)). 대역이 이미 인식적 지위를 나눈다 — 600 저자의 주장 → 400 내 결정 → 200 내 원칙. 이 구분을 **형식화하되 새로 만들지 않는다** |
| **중단** | gold set에서 「저자가 말했다」가 「내가 믿는다」로 라벨링된 사례가 하나라도 나오면 의미 단위를 다시 정한다 |

### R3 · 인용률이 낮은 것을 방치로 오인한다

| | |
|---|---|
| **발생 조건** | 링크 통계만 보고 문서의 가치를 판단할 때 |
| **관측** | **이번 조사에서 실제로 저질렀다.** 601 Books 챕터의 외부 인용률 6%를 방치의 증거로 읽었는데, `개발 서적 노트 가이드라인`이 「단방향 링크만 사용한다. 허브 → 장 인덱스 → 개별 노트」를 규정하고 있었다. 인용률 6%는 고장이 아니라 설계다 |
| **완화** | 통계를 해석하기 전에 **그 대역의 가이드라인 문서를 먼저 읽는다.** `000 Index/Maintenance/가이드라인/`에 9개, `디렉토리 철학/`에 9개가 있다 |
| **중단** | — (해석 규율이므로 중단 조건이 아니라 절차로 둔다) |

### R4 · hub 발 링크가 통계를 부풀린다

| | |
|---|---|
| **발생 조건** | `links_to`를 세어 「이 문서가 쓰인다」고 판단할 때 |
| **관측** | 전체 9,544건 중 hub 출발이 **2,368건(25%)**. hub는 목록 나열이라 의미 관계가 아니다. `principle` 인용률이 hub 포함 94/94(100%) → 제외 81/94(86%)로 바뀐다 |
| **완화** | 모든 관계 통계에서 hub 발 링크를 제외하고, 제외 여부를 숫자와 함께 적는다 |
| **중단** | — |

### R5 · 900이 그래프 밖이라 계보가 조용히 끊긴다

| | |
|---|---|
| **발생 조건** | 「이 믿음이 어떻게 변했는가」를 물을 때 |
| **관측** | `900 Archive/Mind Compiler/_Question.md`는 Q3이고, **답이 확정된 상태로 보관됐다**(v1.0, 2026-02-01). 그 결론이 현재 `500 Mind Compiler/Q7`·`Q2`에서 계속 작동하는데 **두 문서 사이에 링크가 없다.** 900은 `EXCLUDED_ZONES`라 질의도 안 된다 |
| **완화** | D3 — 질문이 문서를 이름으로 지목할 때만 손으로 편입한다. archived 상태와 시점을 함께 적는다 |
| **중단** | archived 결론이 현재 asserted 사실로 자동 승격되는 경로가 하나라도 생기면 즉시 되돌린다 |

## 2군 — 계획이 예상한 위험

### R6 · 문서 유형과 실제 지식 개체를 혼동한다

| | |
|---|---|
| **발생 조건** | `v:Principle`(원칙 유형 문서)을 실제 원칙 클래스로 재사용할 때 |
| **상태** | **차단됨 (2026-08-26).** 문서 13종에 `Document` 접미를 붙여, 재사용할 이름 자체가 없다 |
| **관측** | 「문서를 합쳤다」와 「원칙을 폐기했다」가 같은 사실이 되는지 본다. 회귀 테스트로 고정한다 |
| **완화** | 기존 문서 어휘를 개명한다. 처음에는 「개명하지 않는다」였으나 실측으로 뒤집었다 ([`decisions.md`](decisions.md) 「어휘 네임스페이스」) |
| **중단** | Phase 1~9 테스트 241개 중 하나라도 의미가 바뀐 채 통과하면 되돌린다 |

### R7 · 안정 ID가 없어 이동·분할에서 정체성을 잃는다

| | |
|---|---|
| **발생 조건** | 문서 rename·move·split·merge |
| **관측** | Phase 13의 시나리오 테스트 6종 |
| **완화** | **압박이 예상보다 작다.** 판정 결과 의미 사실의 현재 개수가 0이므로, 마이그레이션할 데이터가 없는 동안 ID 정책을 실험할 수 있다 |
| **중단** | gold set 50개를 만든 뒤에도 ID 정책이 미정이면, 그 시점의 정책으로 동결하고 이후 변경은 마이그레이션 비용을 적고 한다 |

### R8 · 의미 라벨링 비용이 감당 범위를 넘는다

| | |
|---|---|
| **발생 조건** | Phase 11 파일럿과 Phase 12 |
| **관측** | 문서당 분 수 · 재라벨링 일치율 · 보류 비율. **기준선이 이미 있다** — `500 Mind Compiler`의 주간 10분·월간 1시간·분기 3시간 리듬이 2026-02-22부터 17주 돌아갔다 |
| **완화** | 절대값이 아니라 **기존 리듬과의 차이**로 잰다 |
| **중단** | 문서당 15분 초과(2회) · 재라벨링 일치 60% 미만 · 기존 방식의 2배 이상 |

### R9 · OWA 추론과 닫힌 세계 검증을 혼동한다

| | |
|---|---|
| **발생 조건** | 「원칙에는 근거가 있어야 한다」를 OWL로 표현할 때 |
| **관측** | Phase 9에서 이미 손으로 확인했다 — `minCardinality`가 위반 0건을 냈다. **이 vault에서 재현된 사실이다** |
| **완화** | 필수 조건은 전부 SHACL. OWL은 형식 의미만 |
| **중단** | 공리 하나가 의도하지 않은 타입을 1건이라도 추론하면 되돌린다 (Phase 9의 `isPartOf` 폴더 764개 사례) |

### R10 · 추론 결과를 철회할 수 없다

| | |
|---|---|
| **발생 조건** | 「재검토 후보」 같은 운영 판단을 물질화할 때 |
| **관측** | 입력 assertion을 철회하고 재빌드했을 때 낡은 결과가 남는지 |
| **완화** | 운영 판단은 물질화하지 않고 질의 시점에 계산한다. rule ID·version·입력 assertion을 기록한다 |
| **중단** | 철회 후 낡은 결과가 남는 경로가 하나라도 있으면 그 규칙을 뺀다 |

### R11 · 기존 CLI·RDF와의 호환성을 깬다

| | |
|---|---|
| **발생 조건** | 어휘 개명, `doc_iri` 변경, 새 빌더가 기존 빌더를 대체할 때 |
| **관측** | 테스트 241개 · `.vault.ttl` 트리플 수 · `vault q` 출력 |
| **완화** | 의미 그래프가 없어도 기존 CLI가 정상 동작해야 한다 |
| **중단** | 테스트가 하나라도 깨진 채 진행하지 않는다 |

### R12 · 기술적 주장과 개인적 믿음을 같은 것으로 만든다

| | |
|---|---|
| **발생 조건** | `Claim`·`Belief`·`Value`·`Interpretation`을 한 클래스로 묶을 때 |
| **관측** | 부정 테스트 — 한 관점의 `Belief`가 무맥락한 전역 `Claim`으로 승격되는지 |
| **완화** | vault가 이미 대역으로 나눠둔 구분(600 저자 → 400 결정 → 200 원칙)을 형식화한다. 주관적 진술에는 관점 주체와 유효 시점을 보존한다 |
| **중단** | gold set에 오분류가 하나라도 있으면 클래스 경계를 다시 정한다 |

### R13 · 교차 영역 연결을 늘리려 근거 없는 관계를 승인한다

| | |
|---|---|
| **발생 조건** | 「개인 경험이 개발 원칙에 영향을 주었는가」류 질문에 답할 때 |
| **관측** | 승인된 관계 중 원문 근거 위치가 없는 것의 비율 |
| **완화** | 공통 단어·같은 태그·Vector 점수만으로 확정하지 않는다. 교차 영역 edge 수를 목표로 삼지 않는다 |
| **중단** | 근거 없는 교차 관계가 승인 그래프에 1건이라도 들어가면 승인 절차를 멈춘다 |

### R14 · 민감한 개인 문서가 밖으로 나간다

| | |
|---|---|
| **발생 조건** | `100 Private Log`를 읽거나, 500의 성찰 문서가 인용한 사적 내용을 옮길 때 |
| **관측** | **경로 규칙만으로는 안 막힌다.** `500/Q7/_Patterns.md`가 100의 문장을 직접 인용한다 (D6) |
| **완화** | 규칙의 축을 「어디를 읽는가」에서 **「무엇을 옮기는가」**로 옮긴다. 근거는 경로만 적고 인용하지 않는다. docs·커밋 메시지·learnings·제안 로그 어디에도 사적 내용을 남기지 않는다 |
| **중단** | 사적 내용이 저장소나 로그에 남은 것이 발견되면 즉시 지우고 절차를 다시 정한다 |

### R15 · 제안 기능이 실제 작업보다 큰 검토 부담을 만든다

| | |
|---|---|
| **발생 조건** | Phase 19 |
| **관측** | 제안 한 건 검토 시간 · 승인율 · 반복 오탐 비율 |
| **완화** | **Phase 19은 보류다** (D2). 이 위험은 현재 활성이 아니다 |
| **중단** | Phase 18의 실사용에서 값이 확인되기 전에는 시작하지 않는다 |

## 관측하지 않기로 한 것

- **자동 추출 오탐** — Phase 19이 보류이므로 현재 활성이 아니다. 재개하면 살린다.
- **트리플 폭증** — Phase 9에서 이미 쟀다(2.81배, 유용한 새 사실 0). 3부는 물질화를 기본값으로 두지 않으므로 재측정할 이유가 아직 없다.

---

## 이 장부의 사용법

Phase가 끝날 때마다 해당 위험의 **관측값을 적는다.** 관측이 없는 채로 다음
Phase로 넘어가지 않는다. 중단 조건에 걸리면 그 자리에서 멈추고, 왜 멈추지 않을
것인지를 적은 뒤에만 계속한다.
