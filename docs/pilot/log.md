**「필요한 단위」는 셋 중 하나로 적는다** — `문서` · `섹션` · `블록`.
한 문서 안에서 갈리면 둘 다 적는다 (예: `문서/블록`).

**「보류」는 개수로 적는다** — 관계를 붙이려다 애매해서 못 정한 것.

## 2차 라벨링 — **최소 7일 뒤**

5개를 고른다. **1차 답을 보지 않고** 처음부터 다시 적는다.

> 7일 간격이 이 파일럿의 전부다. 짧으면 기억이 남아서 일치율이 부풀려지고,
> 그러면 아무것도 측정하지 못한 채 「할 만하다」는 답만 나온다.

| # | 문서 | 분 | 1차와 같은 개체를 뽑았나 | 같은 관계를 붙였나 | 다르다면 |
|---|---|---|---|---|---|
| | | | | | |
| | | | | | |
| | | | | | |
| | | | | | |
| | | | | | |

**「다르다면」에 셋 중 하나를 적는다.**

```
1차가 맞다     2차가 맞다     둘 다 말이 된다   ← 이게 제일 중요하다
```

**「둘 다 말이 된다」가 많으면 사람이 틀린 게 아니라 어휘가 너무 넓다는 뜻이다.**

## 판정 (2026-08-26, 1차 라벨링 완료)

### 필요한 단위

| | |
|---|---|
| **문서로 충분** | 1 · 4 · 5 · 7 · 9 · 11 — **6건** |
| **항목이 필요** | 8 · 10 — **2건** |
| 붙일 관계가 없음 | 2 · 3 · 6 — 3건 |

라벨을 붙인 8건 중 **6건(75%)**이 문서 단위로 충분했다.

> **주의 — 이 비율은 부풀려져 있다.** 파일럿이 8번을 **일부러** 골랐다. 항목 단위가
> 필요한 문서는 vault 전체에서 **13개(0.3%)**뿐이고 파일럿에서는 2/11(18%)로 잡혔다.
> 실제 분포는 훨씬 문서 쪽으로 기운다.

### 분기 규칙 적용

| 비율 | 분기 | |
|---|---|---|
| 80% 이상 | 규모를 줄인다 | |
| **50 ~ 80%** | **혼합** | ← **75%. 여기다** |
| 50% 미만 | 계획대로 | |

**판정: 혼합.** 그리고 혼합의 모양이 실측으로 정해졌다.

```
기본        문서 단위. 4,006개 문서가 여기 해당한다
예외        13개 문서만 항목 앵커
              500 Mind Compiler  Q1~Q7 의 _Insights 6 · _Patterns 6
              900 Archive        Q3 의 _Insights · _Patterns
```

**그 13개는 이미 항목 번호를 갖고 있다.** 「인사이트 10」이 그대로 앵커다. 새 ID를
만들 필요가 없고, **그 번호로 가리키는 관행도 이미 있다**(10번 문서에서 4건 확인).

### 형식 비교 — 파서가 무엇을 보는가

| | A frontmatter | B 본문 섹션 | C sidecar |
|---|---|---|---|
| 타입 있는 엣지가 되나 | ✅ 파서 한 줄 | ❌ `links_to`로만 | ❌ vault 밖 |
| 항목을 가리킬 수 있나 | ❌ 문서 단위뿐 | 🟡 항목 아래 쓰면 | ✅ 번호로 |
| 본문을 더럽히나 | 아니오 | **예** | 아니오 |
| 원문과 어긋날 위험 | 없음 | 없음 | **있음** |

**A와 C가 서로를 보완한다.** A는 문서 단위 관계에 쓰고, C는 13개 항목 문서에 쓴다.
B는 관계 이름이 파서에 안 남아서 **정본으로는 부적합하다** — 사람이 읽는 산문으로는
이미 잘 쓰이고 있으니(4번의 「관통 원칙은 A와 B」) 그건 그대로 두면 된다.

다만 `violates`는 C29(따른 원칙과 어긴 원칙)의 핵심이므로, **파일럿 11개가

`contradicts`는 승인 근거가 강했는데(C03·C06) **한 번만, 그것도 예상과 다른
자리에서** 나왔다. 문서 사이의 충돌이 아니라 한 문서 안의 모순이었다.

### 못 잰 것 — 시간

**문서당 소요 시간을 못 쟀다.** 라벨링을 대화로 진행해서 왕복 시간과 조사 시간이
섞였고, 토마토의 실제 소요를 분리할 수 없었다.

그래서 **중단 기준 중 둘을 판정할 수 없다.**

| 관측 | 실측 | 판정 |
|---|---|---|
| 문서당 15분 초과 | **못 잼** | — |
| 기존 방식 대비 2배 초과 | **못 잼** | — |
| 보류 30% 초과 | 보류 1건 / 11건 = **9%** | ✅ 통과 |
| 재라벨링 일치 60% 미만 | 7일 뒤 | 대기 |

**시간을 재려면 2차 라벨링에서 재야 한다.** 어차피 혼자 하기로 되어 있으므로
거기서 스톱워치를 쓰면 된다.

### Phase 12·13·14로 넘길 입력

- **의미의 최소 단위** — 문서. 예외는 13개 문서의 항목이고, 그 항목엔 이미 번호가 있다
- **형식** — A(frontmatter) + C(sidecar) 병용. B는 사람이 읽는 산문으로만
- **실제로 쓴 어휘** — `derived_from` `as_of` `needs_review` `applies` `informs`
  `contradicts` `diverges_from` `expresses` `status` `source_unknown` (10개)
- **한 번도 안 쓴 어휘** — `violates` `answered_by` (Phase 14 삭제 후보, 단 확인 필요)
- **파서 변경** — `vault/graph.py:83`의 튜플에 관계 필드를 더한다. 한 줄
- **`derived_from`의 대상이 문서가 아닐 수 있다** — `experience`(3번), vault 밖
  경로(7번). 파서가 이걸 「깨진 링크」로 세면 안 된다
- **`as_of`의 대상이 둘이다** — 사건이 일어난 때와 적은 때. 10·11번에서 6일·9일 차이

### 900을 그래프 밖에 두는 대가

9번에 붙인 `status: archived` · `as_of` · `needs_review`가 **파서에 하나도 안
잡힌다.** `EXCLUDED_ZONES` 때문이다. 그리고 9번의 깨진 링크 5건도 `vault lint`가
못 잡는다.

**D3(900은 문서 단위로 참여)을 지키려면 그래프가 900을 부분적으로라도 읽어야 한다.**
지금은 「질문이 지목한 문서만 손으로 넣는다」고 정했는데, **넣을 자리가 없다.**
