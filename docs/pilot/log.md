**「필요한 단위」는 셋 중 하나로 적는다** — `문서` · `섹션` · `블록`.
한 문서 안에서 갈리면 둘 다 적는다 (예: `문서/블록`).

**「보류」는 개수로 적는다** — 관계를 붙이려다 애매해서 못 정한 것.

## 2차 라벨링 — **최소 7일 뒤**

5개를 고른다. **1차 답을 보지 않고** 처음부터 다시 적는다.

> 7일 간격이 이 파일럿의 전부다. 짧으면 기억이 남아서 일치율이 부풀려지고,
> 그러면 아무것도 측정하지 못한 채 「할 만하다」는 답만 나온다.

| # | 문서 | 분 | 1차와 같은 개체를 뽑았나 | 같은 관계를 붙였나 | 다르다면 |
|---|---|---|---|---|---|
| | | | | | |
| | | | | | |
| | | | | | |
| | | | | | |
| | | | | | |

**「다르다면」에 셋 중 하나를 적는다.**

```
1차가 맞다     2차가 맞다     둘 다 말이 된다   ← 이게 제일 중요하다
```

**「둘 다 말이 된다」가 많으면 사람이 틀린 게 아니라 어휘가 너무 넓다는 뜻이다.**

## 라벨링 중에 나온 것

어휘 8+4개로 표현이 안 되거나, 예상과 다르게 나온 것.

| 문서 | 무엇 |
|---|---|
| 1·2 | **`contradicts`가 아니었다.** 두 결정이 어긋난 게 아니라 같은 유형의 문서가 어쩌다 둘 생긴 것. heuristic이라 맞고 틀림이 성립하지 않는다 |
| 1 | `decision`과 `tradeoff`는 **한 타이밍에 같이 만들어진다.** derivedFrom도 contradicts도 아닌 「짝」이다. 어휘에 이 관계가 없다 |
| 3 | **`derived_from`의 대상이 문서가 아닐 수 있다.** `experience` 같은 키워드를 받아야 한다. 파서가 이걸 「깨진 링크」로 세면 안 된다 |
| 3 | **링크할 행위 문서가 아예 없다.** 실무에서 최적화하고 원칙만 남겼다. 「안 적었다」가 아니라 **「적을 대상이 없다」** |
| 4 | **`applies`가 이미 말로 적혀 있다.** 「관통 원칙은 A와 B」 형식. 그 아래 「관련:」과 구분해서 쓴다 |
| 4 | **`as_of`가 기술 문서에서 나왔다.** 개인 문서에서만 나올 줄 알았다. v1 결론을 v2가 조건부로 정정한다 |
| 4 | **`needs_review`가 `elevate.hint`로 이미 있다.** vault에 장치가 먼저 있었다 |
| 4 | **승격은 일어났는데 역방향 링크가 없다.** 패턴 4가 `pytest-xdist 실전 튜닝`으로 승격됐는데 원칙 쪽에서 출처를 못 찾는다 |
| 5 | **`diverges_from`이 안 나왔다.** 시험하려고 고른 문서인데 저자와 갈리는 지점이 없다. 추출·맥락화는 변형이 아니다 |
| 5 | **「명료한 링크」의 대가 — 대표노트 1개가 챕터 14개가 됐다.** 정확해지는 대신 손으로 걸 링크가 14배다 |
| 5 | `builds_on`이 산문에만 있었다. 「전제」라고 명시했는데 frontmatter는 비어 있었다. **작동하는 유일한 관계인데 안 쓰고 있었다** |
| 3·5 | `> 원본:` · `**Source**:` 가 **둘 다 산문**이었다. 날짜·수치·책 제목은 있고 링크가 아니다 |
| 6 | **`derived_from`은 받는 쪽에 부담을 주지 않는다.** 관계가 한 방향이라 원본 문서에는 적을 게 없다 |
| 7 | **`diverges_from`이 드디어 나왔다.** 형태가 예상과 다르다 — 저자를 부정하지 않고 「그 비판은 순수 TDD에 유효하다」고 인정한 뒤 자기 변형은 다르다고 갈라선다 |
| 7 | **관계의 대상이 vault 밖일 수 있다.** 「현행 TDD SKILL」의 정본이 `~/ai-ops-skills/2-verification/tdd`다. 3번의 `experience`와 다른 종류의 같은 문제 |
| 7 | **「해소 안 된 것」을 문서가 스스로 적는 패턴이 두 번째다.** 4번은 `elevate.hint`, 7번은 본문의 「남은 긴장」 |
| 8 | **문서 단위가 여기서 깨진다.** 19개 항목이 각각 다른 `as_of`를 갖는다 |
| 8 | **잃는 것은 링크가 아니라 출처다.** 위키링크는 이미 항목 안에 있고, 그래프에는 문서 단위로만 보인다 |
| 8 | **항목 번호가 이미 안정 ID 역할을 한다.** 「인사이트 10」이 그대로 앵커다 |
| 9 | **900에는 frontmatter가 없다.** 형식 A를 쓰려면 새로 만들어야 한다 |
| 9 | **Phase 13의 문제가 실물로 있다.** Q3의 하위 질문 5개가 Q2로 이관됐는데 링크가 상대 경로라 **전부 깨졌다** |
| 9 | **900이 그래프 밖이라 `vault lint`가 이 깨진 링크 5건을 못 잡는다.** 조용한 실패다 |
| 10 | **항목 번호로 가리키는 관행이 이미 있다.** `Q7 인사이트 20` 형식으로 4건. 8번의 추측이 실제 사용례로 확인됐다 |
| 10 | **문서와 지식 개체가 1:1인 사례.** 본문이 「Q7 인사이트 20 — 이 글 자체」라고 적는다 |
| 10·11 | **`as_of`의 대상이 둘이다.** 사건이 일어난 때와 적은 때. 10번 6일 · 11번 9일 차이 |
| 11 | **한 문서에 관점 주체가 둘이다.** 대화 기록이라 「정호의 응답」과 「나의 답변」이 섞여 있다 |

## 실측 — 209 Principles 의 근거 기록 실태

> **2026-08-26 전수 조사로 정정.** 파일럿 중의 거친 집계(없음 50 · 빈 것 33 ·
> 채움 5)는 `> 원본: [[...]]` 형태만 세고 **산문 서술을 놓쳤다.** 「대부분 안
> 채웠다」는 서술이 과장이었다.

```
type: principle              86      (209 폴더 90 = 원칙 86 + hub 2 + template 2)

> 원본: 블록 없음             48      55.8%
블록만 있고 비어 있음           3       3.5%
채워짐                       35      40.7%
```

채워진 35개의 형태가 **시기로 갈린다.**

```
위키링크만        17      2026-01~04 에 만든 원칙에 몰려 있다
산문만            16      2026-04-29 이후에 몰려 있다
혼합               2
```

어느 시점부터 「링크를 걸던」 습관이 「측정값을 문장으로 적는」 쪽으로 바뀌었다.

### 계보는 이미 이어져 있다 — 링크가 아닐 뿐

날짜가 적힌 16건의 **그 날 Day Note가 100% 존재한다.**

```
Day Note 가 그 원칙을 역링크함        9건
하루 차이로 이어짐                    5건    저녁에 작업하고 다음날 적었다
실제로 끊긴 것                        2건
```

**「근거가 없다」가 아니라 「근거가 링크가 아니다」였다.**

### `principle → case` 1건도 진짜가 아니다

그 1건은 `000 Index/Maintenance/Vault 온톨로지 — 스키마 정본.md`가 **예시로 건**
링크다. **진짜 원칙 문서가 사례를 가리키는 것은 0건이다.**

### 책에서 뽑은 원칙은 책과 완전히 단절돼 있다

**`600 Content Observatory` → `209 Principles` 링크가 vault 전체에 0건이다.**
Object Design 11개, Ousterhout 계열 4개, ETC 원칙 등이 원본 블록도 없고 책 쪽에서
오는 링크도 없다.

### `derived_from` 을 기계로 채울 수 있는 후보

```
Day Note → 원칙 링크          33쌍     원칙 28/86 · Day Note 18/341
created ±1일                  20쌍     60.6%
일지가 먼저 (−2~−5일)           5쌍     ← 이쪽이 「근거 → 원칙」 순서에 더 맞다
역링크로 복원 가능한 원본        38개     원본 없는 51개 중
```

**2026-03-23이 특히 선명하다.** 그날 일지가 세 원칙을 가리키고 사흘 뒤 그 셋이
한꺼번에 만들어졌다. 그리고 그날이 `A Philosophy of Software Design`과
`The Pragmatic Programmer`의 완독일이다. **책 → 일지 → 원칙 계보가 데이터에는
남아 있는데 링크로는 어디에도 안 적혀 있다.**
