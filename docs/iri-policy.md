## 왜 경로인가

### 이름은 이미 탈락했다

Phase 3 실측이 근거다 ([`learnings/phase03-qa.md`](../learnings/phase03-qa.md)).

| 고장 | 규모 |
|---|---:|
| 같은 이름, 다른 파일 | 이름 66개 · 파일 244개 |
| 같은 글자, 다른 코드포인트 (NFD/NFC) | 파일 1,091 · 링크 5,341 |
| 대소문자만 다른 이름 | 3 무리 |

66개 이름이 244개 파일을 가리킨다. **주어가 확정되지 않으므로 문장이 성립하지 않는다.**

### 경로 IRI가 「깨진다」는 게 무엇인지 먼저 정리했다

**RDF 그래프도 파생물이다.** SQLite 그래프처럼 매번 다시 만든다. 그러면 문서를
옮겨도 아무것도 안 깨진다 — 다음 빌드에서 IRI가 달라질 뿐이고, **이전 IRI를
기억하는 게 아무것도 없다.**

진짜 깨지는 건 **재빌드 밖에서 IRI를 붙잡고 있는 것이 생길 때**다.

| 언제 | 예 |
|---|---|
| 그래프 옆에 뭘 저장할 때 | 「이 문서에 대한 내 메모」 · 추론 결과 캐시 |
| 시계열을 쌓을 때 | 「3월에 이 문서의 `builds_on`은 3개였다」 |
| 남의 데이터와 합칠 때 | 다른 저장소의 트리플이 우리 IRI를 가리킴 |
| 공개해서 남이 인용할 때 | |

**지금 로드맵에 이 중 아무것도 없다.** Phase 9의 TRPG 코퍼스 병합조차
**둘을 같이 재빌드하면** 경로로 된다.

### 그래서 비용이 정당화되지 않는다

정본의 원칙이 그대로 적용된다 — **「필요한 질의가 없으면 안 넣는다」.**
ULID가 답할 수 있게 만드는 질의가 지금 없다.

그리고 **지금 심으면 학습 기회를 잃는다.** 이 프로젝트는 「경로 IRI가 언제
깨지는지」를 손으로 겪어보려는 것이고, 미리 피하면 Phase 9에서 「왜 안정 ID가
필요한가」를 근거 없이 말하게 된다. Phase 1에서 「정규식이 깨지는 지점 목록」을
만든 것과 같은 방식이다.

## 경로 IRI가 깨지는 지점 — 알고 시작한다

Phase 1의 「깨지는 지점」 목록과 같은 성격이다. **모른다고 적는 것도 목록의 값어치다.**

| 깨지는 입력 | 어떻게 |
|---|---|
| **문서를 옮긴다** | 다른 리소스가 된다. **최근 2주에 두 번 있었다** — `320 Career` 재편, `800 TRPG` 분리 |
| **문서명을 바꾼다** | 같음 |
| **NFD로 저장된 파일** | 정규화하지 않으면 같은 문서가 두 IRI를 갖는다. **파일 1,091개** |
| 경로에 공백 | IRI에 공백은 못 들어간다. `%20`으로 인코딩한다 |
| 경로에 한글 | **인코딩하지 않는다.** IRI는 유니코드를 허용한다 (URI와 다른 점) |

**「경로도 식별자가 아니다」가 정확한 표현이다.** 그냥 더 긴 이름이다.
Phase 3의 결론이 그대로 확장된다.

| 고장 | 이름 | 경로 |
|---|---|---|
| 겹친다 | 66건 | 안 겹친다 |
| 바뀐다 | 개명 | **재배치 — 일상이다** |
| 정규화 | NFD/NFC | **똑같이 있다** |

## 전환 조건

> **재빌드 밖에서 IRI를 참조하는 것이 처음 생길 때 ULID로 옮긴다.**

후보는 위 표의 넷이다 — 그래프 옆 저장 · 시계열 · 코퍼스 병합 · 공개.

Phase 9에서 이 조건을 검토한 결과, 두 코퍼스를 함께 조회해야 하는 질의가 아직
없어 병합을 보류했다. 항상 함께 재빌드한다면 안정 ID 전환 조건도 충족되지 않는다.
아카이브 쪽에 별도 데이터나 이력을 쌓기 시작하면 다시 검토한다.

### 왜 UUID가 아니라 ULID인가

vault에 이미 [[UUID VS ULID]]가 있다. 지식 베이스에는 ULID가 낫다 —
**시간 순으로 정렬되므로** `01J8…`만 봐도 대략 언제 만든 문서인지 알 수 있고,
`created`와 정보가 겹쳐 사람이 읽을 때 단서가 된다.

### 「필드 상한 6」 과 충돌하지 않는다

정본의 근거는 **「수집은 원본의 10%」**이고, 그건 **사람이 손으로 채우는 부담**에
대한 원칙이다. `created`가 이미 자동이고 `id`도 `vault new`가 넣으면 사람은
아무것도 안 한다.

진짜 비용은 다른 데 있다 — **4,204개 문서의 frontmatter가 한 줄씩 길어지고
매일 눈에 띈다.**

## 전환을 싸게 만든다

지금 할 일은 「경로냐 ULID 냐」를 고르는 것이 아니라 **나중에 바꿀 수 있게 만드는 것**이다.

```python
def doc_iri(relative):
    """Mint the IRI for a document. The ONE place identity is decided."""
```

- IRI를 만드는 자리를 **함수 하나로 모으고 테스트를 붙인다**
- 전환은 이 함수를 고치는 일이 된다. 그래프가 파생물이므로 다시 빌드하면 끝이다
- **호출부가 IRI의 모양을 알면 안 된다.** 문자열을 조립하는 코드가 여기저기 생기면
  격리가 무너진다

## 네임스페이스

```turtle
@prefix v:      <https://tomato.vault/schema/> .   # 우리 어휘
@prefix doc:    <https://tomato.vault/doc/> .      # 문서
@prefix folder: <https://tomato.vault/folder/> .   # 폴더 (2026-08-24 추가)
@prefix tag:    <https://tomato.vault/tag/> .      # 태그 (Phase 8에서 판정)
```

### 폴더를 왜 따로 두나 (2026-08-24)

**파일이 아닌 것에 IRI를 주는 첫 사례다.** SQLite에서는 폴더를 노드로 만들려면
가짜 행이 필요해서, 대신 폴더 노트를 폴더의 대역으로 썼다. 그 타협 때문에
`part_of`가 형제 파일을 가리키고 계층이 2단에서 끊겼다.

RDF에서는 IRI가 공짜라 그 타협이 필요 없다. 경위와 실측은
[`../learnings/phase06-qa.md`](../learnings/phase06-qa.md) 의 「모델링」 절.

**`doc:`와 `folder:`를 가른 이유**는 같은 경로가 둘 다일 수 있어서다.
`200 Dev/Network`는 폴더이고, `200 Dev/Network/Network.md`를 옮기면 `.md`를 뗀
IRI는 `doc:200%20Dev/Network/Network`다. 네임스페이스를 나누지 않으면 **폴더와
문서가 같은 이름을 두고 부딪힐 수 있다.** 가르면 절대 안 부딪힌다 —
[[네임스페이스 — 어휘 충돌을 푸는 법]]이 말하는 그 성질이다.

**IRI는 주소가 아니라 이름이다.** 접속될 필요가 없고 도메인을 소유하지 않아도 된다.
URL 모양인 이유는 **전역 유일성을 값싸게 얻으려고** — 도메인은 세상에 하나씩만 있으므로
소유권 체계를 빌려 이름 충돌을 없앤다.

`tomato.vault`는 소유하지 않는다. 그래도 유일하다. 누군가 그 도메인을 사도
**우리 IRI가 틀려지는 것은 아니다** — 다만 그쪽도 같은 이름을 쓰면 이론상 충돌한다.

`w3id.org` 같은 영구 식별자 서비스를 안 쓰는 이유는 **공개할 어휘가 아니기 때문**이다.
공개하게 되면 그때 옮긴다. 이것도 `doc_iri()` 격리 덕에 함수 하나다.
