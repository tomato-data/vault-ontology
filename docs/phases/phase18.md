# Phase 18 — 의미 질의와 설명 계층

> 그래프를 사람이 사용할 수 있는 답으로 바꾼다.

## 목표

Phase 10의 역량 질문을 CLI 또는 Python API에서 실행하고, 결과와 함께 선택 이유·
관계 경로·원문 근거를 반환한다. SPARQL 문자열을 노출하는 것만으로는 운영 기능이 아니다.

## Step 1 — 질문 API를 정의한다

초기 명령 후보:

```text
lineage       사건 → 주장 → 원칙 → 절차 계보
evidence      원칙·결정의 근거
conflicts     충돌하는 주장과 영향 대상
impact        원칙·근거 변경의 영향 범위
review        현재 재검토 후보와 이유
explain       특정 결과의 derivation
cross-domain  경험·철학·개발·커리어 사이의 근거 있는 접점
```

명령 이름은 구현 시 기존 CLI와 충돌 여부를 확인해 확정한다. 범용 SPARQL 실행보다
반복 사용하는 질문을 안정된 계약으로 먼저 제공한다.

## Step 2 — 답의 구조를 고정한다

각 결과에는 다음을 포함한다.

- 지식 개체의 사람이 읽는 이름과 ID
- 연결된 Markdown 경로와 section/block
- 관계 종류와 방향
- asserted·inferred·proposed 상태
- 출처와 승인 정보
- 결과가 나온 관계 경로
- 불확실하거나 누락된 정보
- 주관적 진술의 관점 주체와 당시/현재 유효 시점

"없음"과 "아직 기록되지 않음"을 구분한다. 열린 세계에서 조회 결과가 없다고 사실의
부재를 단정하지 않는다.

교차 영역 답은 연결 수를 많이 보여주는 것이 목표가 아니다. 예를 들어 “개인 경험이
어떤 개발 원칙에 영향을 주었는가?”라는 질문에는 승인된 `motivates`·`derivedFrom`
경로와 양쪽 원문을 제시한다. 의미 유사 후보만 있으면 확정 답이 아니라 별도 후보로
표시한다.

## Step 3 — gold answer 회귀 테스트를 만든다

Phase 12의 50개 문서와 Phase 10의 기대 답을 연결한다.

- 정확한 결과 집합
- 관계 경로
- 제외되어야 할 제안
- 설명에 포함될 근거
- 결과가 없어야 하는 반례

텍스트 출력 전체 snapshot보다 구조화된 answer object를 먼저 테스트한다.

## Step 4 — 저장 엔진을 숨긴다

질문 API가 rdflib 구현 세부에 직접 묶이지 않도록 한다. SQLite·SPARQL·Python rule 중
어느 경로가 적합한지는 질문별 실측으로 결정한다. 모든 것을 RDF 엔진으로 옮기는 것이
목표가 아니다.

## Step 5 — 실제 사용 시험을 한다

최소 2주 동안 다음을 기록한다.

- 어떤 질문을 몇 번 실행했는가
- 기존 grep·Dataview·`q near/path`로 충분했는가
- 답을 실제 결정이나 문서 수정에 사용했는가
- 설명을 신뢰할 수 있었는가
- 잘못된 결과를 수정하는 데 얼마나 걸렸는가
- 교차 영역 연결이 새로운 성찰이나 실제 판단으로 이어졌는가

## Vector 경계

VectorDB는 이 Phase에서 구현하지 않는다. 나중에 연결할 수 있도록 결과 후보가 다음
식별자를 받을 계약만 둔다.

```text
chunk_id → artifact IRI → section/block → knowledge entity
```

Vector 점수는 검색 신호이며 asserted graph에 들어가지 않는다.

## 산출물

- semantic query API/CLI
- 구조화된 answer와 explain 모델
- competency question 회귀 테스트
- 2주 사용 로그와 기존 도구 대조
- Vector 연동 인터페이스 문서

## 완료 조건

- [ ] 우선 역량 질문이 명령 또는 API로 실행된다.
- [ ] 모든 답에서 원문과 관계 근거로 이동할 수 있다.
- [ ] proposed 사실이 기본 답에 섞이지 않는다.
- [ ] 없음과 미기록을 구분한다.
- [ ] 기존 도구로 충분한 질문을 중복 구현하지 않는다.
- [ ] 최소 2주간 실제 사용 결과가 있다.
- [ ] 개발·개인·철학을 잇는 질문에서 근거 없는 연결을 확정 답으로 내지 않는다.

## 난이도와 위험

**난이도: 높음. 정확한 그래프를 유용한 답으로 바꾸는 제품 설계 단계다.**

SPARQL이 정답을 반환해도 사람이 이유를 이해하지 못하면 사용할 수 없다. 반대로
자연어 설명이 매끄러워도 근거 경로가 틀리면 위험하다. 구조화된 답을 정본으로 두고
자연어는 그 위의 표현 계층으로만 만든다.
