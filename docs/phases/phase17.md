# Phase 17 — 목적 제한 추론과 운영 규칙

> 트리플 증가량이 아니라 새 역량 질문으로 추론의 가치를 판정한다.

## 핵심 구분

모든 파생을 OWL에 넣지 않는다.

| 종류 | 예 | 구현 후보 |
|---|---|---|
| 형식 의미 | 하위 클래스, 역관계 | RDFS/OWL |
| 그래프 경로 | 사건 → 주장 → 원칙 → 절차 | SPARQL property path/CONSTRUCT |
| 검증 | 원칙에 근거가 없음 | SHACL |
| 운영 판단 | 폐기 근거에 의존하므로 재검토 | 명시적 rule/SQL/SPARQL |
| 검색 후보 | 내용이 비슷함 | Vector 외부 축 |

운영 상태는 시간이 지나며 철회될 수 있다. OWL의 단조 추론만으로 `NeedsReview`를
영구 사실처럼 물질화하지 않는다.

## Step 1 — 질문에 연결된 규칙만 선정한다

초기 후보:

- 무효화된 주장에 근거한 원칙을 재검토 후보로 계산
- 사건 → 주장 → 원칙 → 절차의 계보 계산
- 서로 모순되는 주장에 의존하는 결정 표시
- 선행 조건을 따라 실행 준비 상태 계산
- 원칙 변경의 절차·프로젝트 영향 범위 계산
- 개인 경험에서 나온 가치가 개발·커리어 결정에 미친 계보 계산
- 서로 다른 영역의 원칙이 같은 사건을 보강하거나 긴장시키는 지점 계산

각 규칙은 하나 이상의 Phase 10 질문을 새로 통과시켜야 한다.

교차 영역 관계는 의미 유사성만으로 추론하지 않는다. 공통 단어, Vector 점수, 같은
태그만으로 `informs`·`motivates`·`contradicts`를 확정하지 않고, 승인된 assertion이나
명시적인 관계 경로가 있을 때만 운영 판단에 사용한다.

## Step 2 — asserted와 derived를 분리한다

- 규칙 입력은 승인된 asserted graph만 사용한다.
- 결과는 inferred/derived graph에 쓴다.
- 규칙 ID와 버전, 사용한 입력 assertion을 기록한다.
- 입력 철회 시 결과를 전부 재계산할 수 있어야 한다.
- 결과를 Markdown에 자동 기록하지 않는다.

## Step 3 — 설명 가능한 derivation을 만든다

결과만 반환하지 않는다.

```text
원칙 P08 — 재검토 후보
  because Claim C31 was invalidated by Evidence S19
  P08 derivedFrom C31
  Procedure R12 operationalizes P08
```

각 결과에서 사용한 관계 경로와 원문 근거를 재구성할 수 있어야 한다.

## Step 4 — 무추론 기준선과 비교한다

각 질문을 세 방식으로 비교한다.

1. 원본 asserted graph 질의
2. query-time path/rule 계산
3. materialized inference

정답, 설명 가능성, 갱신 비용, 실행 시간을 비교한다. Phase 9처럼 질의 시점 계산이
충분하면 물질화하지 않는다.

## Step 5 — 부정·철회·시간을 시험한다

필수 fixture:

- 근거가 나중에 복구됨
- 모순 주장이 해결됨
- 제안이 거절됨
- 원칙이 supersede됨
- 같은 규칙을 두 번 실행함
- 이전 ontology/rule 버전의 결과가 남아 있음

## 산출물

- 역량 질문에 연결된 규칙 세트
- rule ID·version·provenance
- query-time과 materialization 비교 보고서
- derivation explanation
- 철회·재계산 테스트

## 완료 조건

- [ ] 최소 한 개 이상의 기존 불가능 질문을 정확히 답한다.
- [ ] 모든 파생 결과에 설명 경로가 있다.
- [ ] 입력 철회 후 낡은 결과가 남지 않는다.
- [ ] OWL·SHACL·운영 규칙의 책임이 섞이지 않는다.
- [ ] 개인 관점과 시점을 제거한 전역 사실을 새로 만들지 않는다.
- [ ] 단순 질의로 충분한 파생을 불필요하게 물질화하지 않는다.
- [ ] 성능보다 정답과 유지 비용을 함께 측정했다.

## 난이도와 위험

**난이도: 매우 높음. Phase 9보다 논리 종류와 시간축이 늘어난다.**

Phase 9 추론은 단조적이었다. 사실을 더하면 결과도 늘었다. 운영 판단은 근거가
철회되거나 상태가 바뀌면 결과를 없애야 한다. 이 비단조성을 OWL에 억지로 넣으면
낡은 경고가 남거나 원인을 설명하지 못한다. 규칙과 상태를 명시적 산출물로 다루어야 한다.
