# 태그 어휘가 언제 늘어도 되는가

> 정본의 규칙을 **뒤집지 않고 정확히 읽었다.** 2026-09-01 실측.
> 진단은 `vault tags --health`, 개별 판정은 `vault tags --judge <태그>`.

---

## 규칙은 어휘를 얼린 적이 없다

스키마 정본이 이렇게 적어놨다.

```
「태그 체계는 유지·검수만 한다.  새 축을 태그로 만들지 않는다」
                                  ↑ 축(axis)이지 값(value)이 아니다
```

**「새 축」은 새 분류 차원이다.** `Mood/` 를 만드는 것과 `Stack/Rust` 를 만드는 것은
다른 일인데, 실무에서 둘 다 「새 태그」로 뭉뚱그려져 **값도 못 늘리는 상태**가 됐다.

규칙의 배경에는 실제 사고가 있다 — hex 색상 태그 30여 건 오염, 그리고
**「배출구가 생기면 배출구가 이긴다」**. 그건 지금도 유효하고, 그래서 축은 계속 막는다.

## 그런데 실태는 과잉이 아니라 미달이었다

```
문서 4,043  ·  어휘 244  ·  부착 3,157
태그 없는 문서 2,078 (51%)
문서당 태그 중앙값 0
```

**절반이 태그가 없고 중앙값이 0이다.** 억제해야 할 대상이 애초에 안 벌어지고 있다.

---

## 축이 두 종류다

| | 축 | 값이 무엇인가 | 새 값 |
|---|---|---|---|
| **지시형** | `Person` `Projects` `Source` `Stack` | vault 밖에 실재하는 것의 이름 | **자유** |
| **판단형** | `Genre` `Topic` `Interests` `Log` `Mind-Compiler` | 누군가 내린 판단 | **근거 필요** |

`Stack/Rust` 는 범주를 발명하지 않는다 — **Rust 가 실재하고 그 노트가 그것에 관한
것**이다. `Genre/입문서` 는 다르다. 다른 낱말 셋도 똑같이 말이 됐을 것이고, 거기가
어휘가 낙서로 바뀌는 자리다.

**1회용도 축의 종류가 뜻을 정한다.** `Person/정준영` 1회는 **한 사람**이지 소음이
아니다. `Genre/입문서` 1회는 누가 낱말을 더듬은 것이다.

---

## 신호 셋

`vault tags --health` 가 내는 것이 이것뿐이고, **「어휘가 너무 크다」는 없다.**

```
split     한 값이 축의 절반을 먹었다.  그 자리가 안 갈린다      판단형에만
scratch   판단형 축에 1회용이 40% 넘게 쌓였다                  판단형에만
unused    태그 자체가 안 붙는다.  가장 큰 숫자가 여기 있다
```

**둘 다 판단형에만 건다.** 지시형에서 한 값이 지배하는 건 「그 얘기를 많이 쓴다」는
뜻이고, 쪼개면 같은 사람 이름이 둘이 된다.

### 2026-09-01 실측

```
Topic    판단형  값  7 · 부착   121 · 고름 0.50   [split] Topic/Mathematics 74/121 (61%)  [scratch] 3/7
Log      판단형  값  9 · 부착   467 · 고름 0.43   [split] Log/Daily-Note 347/467 (74%)
Genre    판단형  값 61 · 부착   247 · 고름 0.87   [scratch] 1회용 27/61
Interests 판단형 값 14 · 부착   100 · 고름 0.81   [scratch] 1회용 6/14
Stack    지시형  값 74 · 부착 1,356 · 고름 0.77
Person   지시형  값 38 · 부착   125 · 고름 0.85

태그 없는 문서 2,078/4,043 (51%)
```

**`split` 이 가리키는 것이 `review` 를 낳은 그 모양이다** — 600 안에서 `source-note`
가 1,252/1,258 이었고, 쪼개니 1,119 · 141 이 됐다. `Log/Daily-Note` 74% 와
`Topic/Mathematics` 61% 가 지금 같은 자리에 서 있다.

## 게이트

```bash
vault tags --judge "Stack/Rust"     [free]         Stack 은 지시형 — 이름 짓는 것뿐
vault tags --judge "Genre/에세이"    [needs-reason] 무엇을 가르는지 적어야 한다
vault tags --judge "Mood/차분함"     [new-axis]     새 축이다 — 정본이 금지한다
vault tags --judge "Stack/Python"   [known]        이미 있다 (232개 문서)
```

종료 코드는 **`free` 일 때만 0** 이다. 나머지는 사람이 정할 일이 남았다는 뜻이라 1을
돌려준다. 에이전트가 이 명령을 지나 태그를 붙이려면 **`free` 를 받아야 한다.**

## 판단형에 새 값을 넣는 근거는 무엇이어야 하나

**「무엇을 가르는가」 한 줄.** 그리고 가장 값진 근거는 `split` 신호다 — 판별력이
죽은 값을 쪼개는 것이면 근거가 이미 숫자로 있다.

```
✓  Log/Daily-Note 이 347/467 을 먹어서 안 갈린다.  Log/Weekly-Note 로 쪼갠다
✗  이 책은 입문서 느낌이라 Genre/입문서 를 만든다
```

---

## 안 바꾼 것

- **새 축은 여전히 금지한다.** hex 오염의 교훈이 거기 있다
- 태그는 **3순위 검색 수단**이다. 온톨로지가 맡는 것은 3·4단계이고 태그의 지위는 그대로다
- 자동 태깅을 열지 않았다. `vault tags` 는 여전히 읽기 전용이고, `--judge` 도 판정만 한다
