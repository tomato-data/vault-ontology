# Verdict — 9 Phase 를 지나 내리는 판단

이 프로젝트는 vault 를 두 번 모델링했다. Phase 1~5 는 SQLite 속성 그래프로,
Phase 6~9 는 RDF/OWL 온톨로지로. 두 번 지어야 무엇이 데이터의 성질이고
무엇이 도구의 한계인지 갈린다 — 그게 두 번 지은 이유였고, 여기서 답한다.

## 프로젝트가 열어둔 질문

| 질문 | 답 |
|---|---|
| 재귀 CTE 로 부족한 순간이 있었나 | **없었다.** Phase 7 에서 여섯 질의 전부 재귀 CTE 로 0.5ms 에 답했다. property path 는 더 짧을 뿐, 못 하던 걸 하게 하지 않았다. |
| 추론이 SQLite 로 못 얻던 사실을 만들었나 | **질적으로 새로운 건 없었다.** 이행 폐쇄(builds_on+)=learning_path, 역링크(linked_by)=near — 둘 다 SQLite 가 질의 시점에 이미 냈다. 추론은 그걸 트리플로 굳혔을 뿐이다. |
| 그 사실이 실제로 필요했나 | **아니다.** 질의 시점 계산으로 이미 충분했다. 물질화는 16.6초 + 3배 저장을 쓰고, 못 답하던 질의를 하나도 열지 못했다. |
| v1(rdflib 상시 운용)으로 갈 가치가 있나 | **없다.** SQLite 가 전 질의에서 10~600배 빠르다. 추론은 16.6초가 들고, 늘어난 트리플의 절반(rdfs:Resource·owl:Thing 14,656개)은 질의력 없는 잡음이다. 이 규모·이 질의에선 rdflib 운용이 SQLite 를 못 이긴다. |
| v2(Rust + Oxigraph)의 근거는 성능인가 학습인가 | **학습이다.** 실측이 스키마 정본의 사전 가설을 지지했다. 성능이 이유라면 SQLite 를 버릴 근거가 없다. 버린다면 추론·SHACL·표현력을 **배우기** 위해서다. |
| vault 의 type 13값에 계층이 있었나 | **있다. 단 의미가 아니라 역할로.** Content/Imported/Structural 3역할만 질의를 번다("내가 쓴 내용만"=Imported·Structural 제외). 가이드가 제안한 6개 의미 묶음은 사후 서사였다. |
| 분리된 두 코퍼스(vault·800 TRPG)를 한 그래프로 합칠 가치가 있나 | **합치기는 공짜지만, 아직 그걸 필요로 하는 질의가 없다.** RDF 는 그래프가 집합이라 두 트리플 뭉치를 더하면 끝이다(IRI 네임스페이스가 충돌을 막는다). 하지만 두 코퍼스를 가로지르는 질의가 생기기 전엔 합칠 이유가 없다. 그 질의가 나올 때 합친다. |

## 그런데 — 온톨로지가 값이 없었다는 뜻은 아니다

위 표는 **운용 가치**를 묻는다. 답은 "이 규모에선 SQLite 로 충분". 그러나
이 프로젝트는 처음부터 **개념 이해가 목적**이었다(2부는 개념이 먼저, 구현은
확인 수단). 그 관점에서 온톨로지가 준 것:

1. **그래프는 집합이다.** links_to 가 10,622 → 9,359 로 준 것, kinds 가 bag/set
   으로 갈린 것, builds_on+ 가 순환에서 저절로 멈춘 것 — 다 한 성질의 여러 얼굴.
2. **domain/range 는 검증이 아니라 추론이다.** 내 스키마의 너무 넓은 domain
   하나가 폴더 764개를 헛 Document 로 만들었다. 이건 SQLite 로는 볼 수 없는
   실패였다 — 값진 실패다.
3. **OWA vs CWA.** OWL 로는 "summary 없으면 위반"을 못 쓴다. 없음은 뺄셈인데
   추론기는 더하기만 한다. Phase 4 의 lint 가 실은 SHACL 의 일이었음을 안다.
4. **표준 어휘와 상호운용.** dcterms 재사용, 고유 관계는 subPropertyOf 로 매담.
   "온톨로지"와 "사설 스키마"의 차이가 여기 있다.

**SQLite 로는 얻을 수 없던 사실이 하나라도 있었나 — 유용한 사실로는 0건.
개념적 교훈으로는 넷.** 정직한 0 과 정직한 넷을 나란히 적는다.

## 결정

- **v1 (rdflib 상시 운용): 하지 않는다.** SQLite 판이 운용의 정답이다. RDF
  산출(.vault.ttl)은 상호운용·백업 용도로만 남긴다.
- **v2 (Oxigraph): 보류하되 근거를 학습으로 고정한다.** 성능이 필요해서가
  아니라, 추론/SHACL/표현력을 더 배우고 싶어질 때 간다. 그 전엔 안 간다.
- **스키마 계층: 3역할을 정본에 반영한다.** 6묶음은 문서로만 남긴다.

## 아직 사람이 답할 칸 — 정직하게

프로젝트가 스스로 정한 성공 기준은 실제 사용량이다.

- Phase 4 이후 2주간 CLI 를 몇 번 썼나 — **미측정.** 이번은 학습용 재구축이라
  2주 실사용 시험을 돌리지 않았다. v1 을 접기로 한 이상, 이 기준은 v2 를
  진지하게 고려할 때 다시 꺼낸다.
- 그중 Dataview·grep 으로 못 했을 질의가 몇 건인가 — 같은 이유로 미측정.

**0건이면 도구를 하나 더 만든 것에 그친다** — 이 프로젝트에 대해선, 도구가
아니라 **이해**를 만들었다고 적는 게 정직하다. 그게 애초의 목적이었다.
