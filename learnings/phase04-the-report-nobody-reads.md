# Phase 4 회고: 아무도 안 읽는 보고서

`schema.py` · `lint.py` · `__main__.py`. 테스트 110개. 실제 vault에 돌려 354건.

Phase의 첫 문장이 **「경고는 무시된다」** 였다. 정본이 실측으로 근거를 적어뒀다 —
`summary` 80자를 프롬프트로 부탁했더니 14%가 위반했고, hex 태그는 청소해도 다시
쌓였다. **권고만으로는 입력을 통제할 수 없다.**

그런데 이 Phase에서 배운 건 그 뒤였다. **강제해도, 거짓 경보가 섞이면 똑같이
무시된다.**

## 582건 — 보고서를 못 쓰게 만드는 실패

vault에 처음 돌렸을 때 깨진 링크가 900건 나왔다. 그중 **582건이 이미지였다.**

```
![[가상화의 종류.jpg]]
![[디플로이먼트-레플리카셋-파드-관계.webp]]
```

Obsidian은 이를 정상 첨부로 처리하지만, 우리 구현은 깨진 링크로 잘못 분류했다.

크래시가 안 났다. 숫자도 그럴듯했다. **다만 65%가 거짓이라 진짜 위반 318건이
그 안에 묻혔다.** Phase 2·3에서 계속 본 「조용히 틀리는」 실패인데, 이번엔
**거짓이 진짜를 가리는** 형태였다.

원인은 Phase 3의 모델이었다.

```python
paths, index = scan_vault(root)   # 둘 다 .md만
```

「읽을 문서」와 「링크가 가리킬 수 있는 것」을 같은 집합으로 봤다. 다른 집합이다.

| | 무엇 |
|---|---|
| `notes` | `.md`만. 이미지를 텍스트로 읽을 수 없다 |
| `index` | **모든 파일.** `![[가상화.png]]`는 정상 링크다 |
| `targets` | 모든 경로. 꼬리 매칭용 |

셋으로 나누니 900 → 328이 됐다. **자료구조 자체에 구분을 반영하면 코드에서
그 차이를 놓치기 어렵다.** Phase 3에서 인덱스를 리스트로 만든 것과 같은 설계다.

## 문서보다 실측이 정확했던 일이 세 번

**1. 오탐 4종이 규칙 하나로 정리됐다.** 가이드는 「네 번 고친 검출기」라며 예외 넷을
피하라고 한다. 실제 데이터를 측정해 보니 **`#` 앞이 공백이거나 줄 시작일 것**이라는 규칙 하나가 네 오탐을
전부 지웠다. 문서에 없던 오탐 둘(위키링크 헤딩 앵커 345건, 단어 중간의 `#` 226건)도
같이 사라졌다.

증상마다 예외를 붙이면 넷이 되고, **근본 규칙을 찾으면 하나가 된다.**

**2. 「의도치 않은 태그」와 「본문 인라인 태그」의 구분이 없어졌다.** 가이드는
`#Stack/Python`을 오탐으로 분류한다. **2026-08-16 태그 일원화 이후로는 위반이다.**
가이드가 쓰인 시점에는 몰랐던 사실이고, 검사 하나가 통째로 사라졌다.

**3. `.vault-lint.json`이 이미 있었다.** 옛 키 이름(`sources`/`targets`/`files`)이라
우리 `load_rules`가 하나도 못 읽었고, 그래서 제외가 0이었다. 설정 파일이 없다고
가정하고 짰는데 있었다.

정본 표에는 있는데 `vault.py`에 구현이 없던 검사다. Day Note가 「미검출 21건」이라
적어둔 그것이다.
