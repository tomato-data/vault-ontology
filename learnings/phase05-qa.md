# Phase 5: Q&A

SQLite 그래프를 짜면서 나온 질문과 답.

## 목적

### Q: 이 그래프는 시각화용인가, 관계를 확인하는 도구인가?

**둘 다 아니다. 질의 가능한 자료구조다.**

「그래프」가 두 가지를 뜻해서 헷갈린다.

| | 무엇 | 이미 있나 |
|---|---|---|
| 그림 | Obsidian 그래프 뷰. 점과 선 | **있다** |
| 자료구조 | 노드·엣지의 집합. 질의할 수 있다 | **없다** |

정본의 첫 문장이 이걸 짚는다.

> 위키링크 24,969개와 태그 263종이 있지만 **기계가 읽을 수 있는 구조가 없다.**

Obsidian 그래프 뷰는 보여주기만 한다. 점 6,000개가 엉킨 그림에서 "CIDR 을 이해하려면
뭘 먼저 읽어야 하나" 를 알아낼 수 없다. **눈으로 보는 것과 물어보는 것은 다른 일이다.**

### Q: 그래서 무엇을 물어보나

```bash
vault q path "CIDR"      # 이걸 이해하려면 뭘 먼저 읽어야 하나
vault q near "CIDR"      # 링크·역링크·같은 태그 이웃
vault q orphans 200      # 아무도 안 가리키는 문서
vault q stats
```

`q path` 가 대표다. `builds_on` 을 여러 단 따라 올라가 학습 순서를 낸다.
vault 최대 깊이가 7 이라 실제로 여러 단을 탄다.

**파일시스템으로도 grep 으로도 못 하는 일이다.** 한 단계는 볼 수 있어도 이행 폐쇄는
못 센다.

### Q: 실용 목적은?

정본이 적어뒀다.

> frontmatter 를 일원화해 **(1) Claude CLI 가 그래프 질의로 vault 를 검색하게 하고**
> (2) 온톨로지를 실전으로 배운다

1번이 실용이다. **에이전트가 vault 를 뒤질 때 쓰는 도구.**

정본은 검색을 4단계로 나눈다.

| 단계 | 수단 | 상태 |
|---|---|---|
| 1 찾아보기 | 전문 검색 | 이미 잘 된다 |
| 2 둘러보기 | 디렉토리 | 이미 잘 된다 |
| **3 태그** | | **온톨로지의 몫** |
| **4 뜻밖의 발견** | | **온톨로지의 몫** |

> 1·2단계는 이미 잘 돌아가며 **대체하지 않는다**

「무슨 파일 있더라」는 지금도 된다. 그래프가 답하는 건 **「이것과 관계있는 게 뭐지」** 다.

### Q: 2부와의 관계는?

**같은 데이터를 두 번 모델링한다.**

```
Phase 5    SQLite 그래프    속성 그래프 = 지식 그래프
Phase 6~9  RDF 트리플       온톨로지
```

같은 질문을 재귀 CTE 로 한 번, SPARQL property path 로 한 번, 추론기로 한 번 푼다.
**답이 같아야 하고 표현력이 달라야 한다.** 그 차이가 이 저장소의 존재 이유다.

Phase 5 가이드의 문장.

> **이 쿼리를 직접 짜보는 게 Phase 5의 핵심이다.** Phase 7에서 SPARQL로 같은 걸
> 한 줄로 쓰게 되는데, 그 한 줄의 가치를 알려면 이 여섯 줄을 손으로 써봐야 한다.

### Q: 시각화는 안 하나?

`node` 와 `edge` 테이블이 있으니 graphviz 나 d3 로 뽑는 건 몇 줄이다.
**다만 그게 이 그래프의 이유가 아니다.** Obsidian 이 이미 그림을 보여주고,
**그림으로는 답이 안 나온다**는 게 출발점이었다.
