# Phase 1: Q&A

frontmatter 파서를 짜면서 나온 질문과 답.

## 스키마

### Q: `builds_on`, `supersedes`가 정확히 뭘 의미하나?

vault 스키마 정본이 **이름 붙인 관계는 이 둘뿐**이라고 못박았다.

**`builds_on` — 선행 지식.** "이 문서는 저 문서 위에 세워졌다."

```yaml
# CIDR.md
builds_on:
  - "[[Subnet mask]]"
```

`Subnet mask`를 모르면 `CIDR`을 읽어도 안 들어온다. 화살표는 나중 것에서 먼저 것으로 간다. 후속 문서가 자기 토대를 가리킨다.

- 이행적. A가 B 위에, B가 C 위에면 A는 C 위에도 있다
- 실측 최대 깊이 7 · 387건
- 상한 3개. 「수집은 원본의 10%」에서 나온 숫자다. 열 개씩 달면 선행 지식이 아니라 관련 문서 목록이다

이행성 덕에 "X를 이해하려면 뭘 먼저 읽나"가 풀린다. 답안지의 `vault q path`가 재귀 CTE로, Phase 7이 SPARQL `builds_on+`로, Phase 9가 추론 물질화로 **같은 질문을 세 번 푼다.**

**`supersedes` — 대체.** "이 문서가 저 문서를 갈아치웠다." 3건.

| | `builds_on` | `supersedes` |
|---|---|---|
| 축 | 논리 | 시간 |
| 대상의 운명 | 둘 다 살아 있다 | 대상은 은퇴한다 |
| 읽기 | 둘 다 읽어야 한다 | 새 것만 읽으면 된다 |

### Q: 왜 이 둘만 이름을 받았나?

위키링크 24,969개는 "여기서 저기를 언급했다"만 말한다. 방향은 있는데 의미가 없다. 참고인지 반박인지 예시인지 알 수 없다.

이름이 있으면 **추론의 재료가 된다.**

```
A builds_on B, B builds_on C  →  A builds_on C     참
A links_to  B, B links_to  C  →  A links_to  C     헛소리
```

의미를 주장할 수 있는 관계만 이름을 받는다. 나머지는 무명으로 둔다. Phase 8에서 `supersedes`를 표준 어휘(`dcterms:replaces`)와 맞출지 판단하게 된다.

## 정규식 파싱이 깨지는 지점

Phase 1 의 진짜 산출물. 표준 라이브러리만 쓰기로 하고 YAML 을 정규식으로
부분 파싱했다. 그 대가가 **어디서 깨지는지 아는 의무**다.

세 칸으로 나눈다. **재보고 안 고친 것**, **안 하기로 하고 테스트로 못박은 것**,
**깨지는 줄 알지만 아직 안 재본 것.** 셋째 칸이 정직해야 목록이 값을 한다.

### A. 재보고 안 고친 것

실측 2026-08-18 · md 6,462개 전체 기준.

| 깨지는 입력 | 실측 | 판단 |
|---|---:|---|
| 빈 frontmatter (`---\n---`) | 0건 | 안 고친다 |
| CRLF 줄바꿈 | 0건 | 안 고친다 |
| 리스트 블록 안의 빈 줄 | 0건 | 안 고친다 |

없는 입력에 대비한 코드는 검증할 수 없고, 검증 안 되는 코드는 썩는다.
중요한 건 이게 "생각 안 해봤다" 가 아니라 **"재보고 안 고쳤다"** 라는 것이다.

### B. 지원 안 하기로 하고 테스트로 못박은 것

| 입력 | 지금 결과 | 고정한 테스트 |
|---|---|---|
| `key: [a, b]` 인라인 리스트 | `[]` | `test_an_inline_scalar_is_not_a_list` |
| 빈 스칼라 `summary:` | `None` | `test_an_empty_value_does_not_swallow_the_next_line` |
| 항목 없는 리스트 키 | `[]` | `test_a_key_with_no_items_is_an_empty_list` |

결정을 테스트로 고정하면 나중에 누가 바꾸려 할 때 테스트가 먼저 말을 건다.

### C. 깨지는 줄 알지만 아직 안 재본 것

| 입력 | 어떻게 깨지나 |
|---|---|
| 여러 줄 스칼라 (`summary: >` 접기) | `fm_get` 이 첫 줄만 읽는다. max 80 이 이걸 배제하진 않는다 |
| 값 뒤의 `# 주석` | YAML 은 주석인데 우리는 값의 일부로 읽는다 |
| 같은 키가 두 번 | `re.search` 가 첫 번째만 읽는다 |
| 리스트 블록 안의 주석 줄 | `-` 가 없어 블록이 거기서 끊긴다 |
| `-` 뒤에 공백 없는 항목 | 매칭 실패. 블록 첫 줄이면 통째로 `[]` |
| `strip("\"'")` | 문자 집합이라 `"'값'"` 의 따옴표를 양쪽에서 다 벗긴다 |
| 중첩 리스트 | 들여쓰기 깊이를 안 본다 |

Phase 4 lint 를 만들면 일부가 드러난다. `builds_on` 대상이 vault 에 없다고
나오는 문서를 열어보면 **파싱이 틀린 건지 링크가 진짜 깨진 건지** 갈린다.

## 실측 — Phase 1 (2026-08-18)

`tools/measure_phase01.py` · md 6,462개.

| 항목 | 전체 | 제외 후 | 답안지(08-11) |
|---|---:|---:|---:|
| 파일 | 6,462 | 3,984 | 6,289 |
| frontmatter | 5,837 (90.3%) | 3,974 (99.7%) | |
| `type` | 5,796 | 3,974 | |
| `summary` | 1,126 | 1,126 | |
| `builds_on` 항목 | 393 | 393 | 387 |
| `supersedes` 항목 | 3 | 3 | 3 |

제외 구역은 `800 TRPG` · `900 Archive` · `.claude` · `.trash` · `.obsidian`.

### 배운 것 1 — 제외 결정이 숫자로 증명됐다

전체에서 `type` 을 가진 5,796개 중 **1,822개가 다른 축**이었다.

```
완제품 1,042 · 원재료 351 · 중간재 316 · 마물 101 · 마족 12
```

안 뺐으면 문서 유형 분포 1위가 `source-note`(1,256) 가 아니라 **완제품**이 된다.
「같은 키, 다른 뜻」이 추상적인 말이 아니다.

답안지 README 는 완제품·원재료·마물 셋만 적어뒀다. **중간재 316 · 마족 12 는
문서에 없던 값이다.** 실측이 답안지 문서보다 최신이 됐다.

### 배운 것 2 — 0 은 의심해야 하는 숫자다

`summary` 80자 초과가 0건으로 나왔다. 기록된 근거는 「실측 14% 위반」이라
158건쯤 나와야 했다. 가설이 정반대로 둘이었다.

| 가설 | 뜻 |
|---|---|
| 마이그레이션이 다 고쳤다 | `vault new` 가 80자를 강제한다. 0건은 진짜 |
| `fm_get` 이 자르고 있다 | 긴 값을 짧게 읽어 위반이 안 보인다 |

**분포를 내서 갈랐다.** `min 2 · median 60 · p95 76 · max 80`.

max 가 정확히 80 인 게 결정적이다. 파서가 자르고 있다면 최댓값이 하필 상한에
딱 떨어질 이유가 없다. 줄바꿈 위치는 문서마다 다르다. 80 에 붙어 있다는 건
**누가 80 에서 막았다**는 뜻이다. p95 76 도 같은 얘기다. 사람이 자유롭게
썼으면 상한 근처에 몰리지 않는다.

0건은 진짜였다. 14% 는 마이그레이션 **이전** 숫자였다.

처음 스크립트가 초과 **건수**만 세고 **분포**를 안 냈다. 건수만 봤으면 두 가설을
못 갈랐다. 계측은 「합격/불합격」이 아니라 분포를 내야 한다.

### 배운 것 3 — 계측 스크립트의 라벨이 거짓말을 한다

분포를 추가하며 옛 출력 줄을 안 지워서 이런 게 나왔다.

```
summary over 80 chars    1,126     <- 옛 줄. len(lengths) 를 찍고 있었다
  over 80       0                  <- 새 줄
```

두 줄이 서로 어긋나서 티가 났다. **한 줄만 있었으면 1,126 을 그대로 믿었다.**
`tools/` 에는 테스트를 안 붙이기로 했으니 출력을 눈으로 검산하는 게 유일한
방어선이다.
